# ADR-001 — Escolha da stack Python/Flask para a EasyFood

## Status

Aceita

## Data

20/09/2026

## Responsável

Gustavo de Carvalho

## Contexto

A disciplina de Software Architecture & Design Patterns evolui a EasyFood a partir de uma API HTTP simples até persistência, camadas e autenticação. O material de sala utiliza Node.js/Express, porém este repositório adopta Python como linguagem de implementação, mantendo o mesmo contrato externo esperado pelo frontend (`GET /restaurants` na porta 3000).

Precisávamos de um framework web leve, próximo ao papel do Express, para validar rapidamente a história de usuário: "Como usuário, quero visualizar os restaurantes disponíveis".

## Alternativas consideradas

1. Node.js + Express (stack das aulas)
2. Python + Flask
3. Python + FastAPI
4. Python + Django REST Framework

## Decisão

Adotar **Python 3 + Flask** como base da API EasyFood.

## Justificativa

- Flask mapeia bem o modelo mental do Express (app, rotas, JSON, middlewares).
- Baixa cerimônia para a primeira versão e para as refatorações seguintes (camadas, auth).
- Ecossistema maduro para SQLAlchemy, JWT e bcrypt, alinhado às missões seguintes.
- Permite cumprir o mesmo contrato HTTP do frontend `index.html` já disponível.

## Consequências

### Positivas

- Evolução incremental idêntica às missões (memória → banco → camadas → JWT).
- Código legível para estudo de decisões arquiteturais.
- Independência de `node_modules` e do runtime Node nesta entrega.

### Negativas / trade-offs

- Documentação de aula precisa ser "traduzida" mentalmente de JS para Python.
- Equipe que só conhece Node precisará de um curto ramp-up.
- Alguns exemplos do material (Prisma) serão substituídos por SQLAlchemy.

## Critérios de revisão

Reavaliar se:

1. O curso exigir entrega obrigatória em Node.js.
2. Surgirem requisitos de tipagem/OpenAPI onde FastAPI se sairia melhor.
3. A equipe padronizar outra stack corporativa.
