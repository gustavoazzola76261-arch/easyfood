# ADR-003 — Persistência com SQLAlchemy

## Status

Aceita (substitui ADR-002 para o mecanismo de armazenamento)

## Data

20/09/2026

## Responsável

Gustavo de Carvalho

## Contexto

O teste de reinicialização (Missão Sprint 03) mostrou que restaurantes cadastrados em memória desaparecem quando o processo Flask encerra. Um dos critérios de revisão do ADR-002 foi atingido: precisamos manter dados entre reinícios.

Nas aulas, a evolução equivalente usa PostgreSQL + Prisma. Em Python, precisamos de um ORM e de um banco relacional compatível com o modelo `Restaurant(id, name, category, rating)`.

## Alternativas consideradas

1. Continuar em memória
2. Arquivo JSON
3. SQLite + SQLAlchemy
4. PostgreSQL + SQLAlchemy
5. MongoDB + ODM

## Decisão

Adotar **SQLAlchemy 2.x** como camada de acesso a dados, com **SQLite** como banco padrão de desenvolvimento (`DATABASE_URL=sqlite:///easyfood.db`), mantendo a URL configurável via `.env` para PostgreSQL quando houver infraestrutura.

## Justificativa

- Resolve a perda de dados ao reiniciar o servidor.
- SQLAlchemy ocupa o papel pedagógico do Prisma (modelo → SQL → migrations/schema).
- SQLite remove fricção de instalação (sem serviço externo) e ainda demonstra persistência real.
- A mesma API de modelos funciona com PostgreSQL trocando apenas `DATABASE_URL`, alinhando-se à Missão 3 sem bloquear quem não tem Postgres local.

## Consequências

### Positivas

- `GET`/`POST` passam a ler e gravar no banco.
- Seed automático na primeira execução garante dados de demonstração.
- Contrato HTTP externo permanece estável.

### Negativas / trade-offs

- Nova dependência e curva de aprendizado do ORM.
- SQLite tem limites de concorrência frente a PostgreSQL em produção.
- `server.py` concentra mais responsabilidades (Express+Prisma no mesmo arquivo) — motivação para a próxima refatoração em camadas.

## Critérios de revisão

Reavaliar quando:

1. Houver deploy multi-instância ou necessidade de concorrência alta → migrar URL para PostgreSQL.
2. Surgirem entidades e relacionamentos complexos exigindo migrations formais (Alembic).
3. O arquivo `server.py` ficar difícil de manter (gatilho da arquitetura em camadas).
