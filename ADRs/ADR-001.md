# ADR-001 — Escolha da stack Python/Flask para a EasyFood

## Status

Aceita

## Data

20/08/2026

## Responsável

Gustavo de Carvalho

## Contexto

Precisávamos de um framework web leve, próximo ao papel do Express, para validar rapidamente a história de usuário: "Como usuário, quero visualizar os restaurantes disponíveis".

## Alternativas consideradas

1. Node.js + Express 
2. Python + Flask
3. Python + FastAPI
4. Python + Django REST Framework

## Decisão

Adotar **Python 3 + Flask** como base da API EasyFood.

## Justificativa

- Flask mapeia bem o modelo mental do Express (app, rotas, JSON, middlewares).
- Ecossistema maduro para SQLAlchemy, JWT e bcrypt, para possiveis evoluções.
- Permite cumprir o mesmo contrato HTTP do frontend `index.html` já disponível.

## Consequências

### Positivas
- Código legível para estudo de decisões arquiteturais.
- Independência de `node_modules` e do runtime Node nesta entrega.

### Negativas / trade-offs

- Maior trabalhor para gerar o frontend final
