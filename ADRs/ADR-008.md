# ADR-008 — Processamento de imagens na API EasyFood

## Status

Aceita

## Data

04/11/2026

## Responsável

Gustavo de Carvalho

## Contexto

Restaurantes e pratos precisam de imagem. Arquivos originais grandes atrasam o app. A aula discutiu Serverless/FaaS, serviço separado ou processamento no próprio servidor.

## Alternativas consideradas

1. Processar dentro da API Flask (Pillow)
2. Microsserviço independente
3. Função Serverless/FaaS
4. Armazenar o arquivo original sem otimizar

## Decisão

Manter o processamento **dentro da API EasyFood**:

- Upload em memória (até 5 MB, JPEG/PNG/WebP)
- Pillow: corrige orientação, reduz até 800 px, grava WebP qualidade 80 com método rápido
- Arquivos em `uploads/dishes` e `uploads/restaurants`
- Caminho salvo em `imageUrl`

## Justificativa

Volume acadêmico baixo, infraestrutura já existe, implementação simples. Serverless não é inadequado; só é desnecessário agora.

## Consequências

### Positivas

- Um único processo, fácil de demonstrar.
- Imagens menores e no formato WebP.

### Limitações

- Consome CPU/memória da API.
- Disco local não serve para várias instâncias (aí avaliaria S3).
- Reavaliar se o volume de uploads crescer.
