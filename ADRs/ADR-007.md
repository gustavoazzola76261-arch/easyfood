# ADR-007 — Serviço compartilhado de e-mail

## Status

Aceita

## Data

04/11/2026

## Responsável

Gustavo de Carvalho

## Contexto

A EasyFood precisa confirmar por e-mail a criação de contas, restaurantes e itens de cardápio. O envio é ação secundária: não pode impedir o cadastro se o provedor falhar.

## Alternativas consideradas

1. SMTP direto (Gmail/servidor próprio)
2. API de e-mail (Resend, MailerSend, SendGrid, Brevo)
3. Fila + worker assíncrono
4. Apenas log no console

## Decisão

Criar `src/modules/shared/email_service.py` com `send_email({to, to_name, subject, header, body, footer})`.

- Sem `EMAIL_API_KEY`: registra o e-mail no terminal (dev/testes).
- Com chave: envia via API HTTP do Resend.
- Cadastros chamam `notify_safely()`, que captura erros do provedor.

## Justificativa

A atividade 6 pede um serviço genérico reutilizável, credenciais no `.env` e independência entre operação principal e e-mail. Resend cobre o caso real; o modo console cobre GitHub Actions.

## Consequências

- O mesmo contrato serve para conta, restaurante e prato.
- Falha de e-mail não desfaz o registro no banco.
- Produção exige remetente verificado no provedor.
